# Secrets the ftn Worker does not read, and therefore does not sync.
#
# The deploy merges the whole shared `common/prd` bus with this project's own
# config and pushes all of it into the Worker. Most of that bus is read by other
# repos — the container agents, other Workers, CI — never by this one, and the
# total crossed Cloudflare's Workers Free limit of 64 variables per Worker
# (secrets + text). The failure surfaces late and cryptically, from the API call
# itself: `wrangler versions secret bulk` reports "This deployment includes 68
# variables" (code 10055) only after it has already been rejected.
#
# So the exception is named here instead: keys that belong to the shared bus but
# are not this Worker's runtime configuration. One key per line; `#` comments
# and blank lines are ignored.
#
# Every entry must be ABSENT from everything the Worker is built from and runs:
# webapp/src, webapp/worker, webapp/scripts, .buildkite, .github and
# wrangler.template.jsonc. That is what makes the list safe rather than a guess,
# and tests/sync-doppler-secrets.test.js enforces it, so the list cannot rot into
# dropping a secret the app actually reads. If a key later becomes used there,
# the test fails and it has to come off this list.
#
# Two kinds of key sit on the bus without being Worker configuration:
#
#   - container-agent tooling. Repo-root `scripts/agent-dev.sh` and `.agents/`
#     read these from Doppler when a devcontainer starts its agent. The values
#     are the same ones, reached directly rather than through the Worker.
#   - build- and CI-time configuration (tokens for the CI provider, SonarCloud,
#     the Sentry upload plugin, the Cloudflare API). The job reads them from
#     Doppler itself; they never need to be Worker variables.
